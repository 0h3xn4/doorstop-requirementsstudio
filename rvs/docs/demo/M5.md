# M5 demo note

> **Point-in-time snapshot.** Written when this milestone was finished: test counts, timings, caveats and command forms were true then and are not updated. For the current state see the user guide, `docs/DECISIONS.md`, `docs/DEVIATIONS.md` and `docs/RELEASE.md`.


```
rvs cr new project "Reduce mass budget" --item SYS-0003 -d "Launcher change"
rvs baseline create project SRR -m "System requirements review" --defer CR-0001="after SRR"
rvs cr new project ...   # edits are attributed with:  rvs import ... --cr CR-0002   (or "use for my edits" in the GUI)
rvs diff project SRR working                    # words marked [-old-]{+new+}; also --format html|docx|pdf|json|csv
rvs export project --vcm --baseline SRR --format pdf -o vcm-at-SRR.pdf
rvs baseline verify project SRR
rvs-studio  ->  tabs Changes | Baselines | Diff, Project > New Baseline…
```
What works
- **Change requests** (`changes/CR-0001.yaml`): create, edit, status log, affected items, "use for my edits" attribution (history `cr` field; edited items listed per request). Statuses and which ones block a baseline are configuration.
- **Baselines**: a manifest of per-item content digests, one commit of the project directory and an annotated Git tag, all offline (pure-Python Git). Approved items become baselined; open change requests block creation unless each is explicitly deferred with a reason; names are never reused; manifest tampering is detected (`baseline verify`, `validate`). Projects inside a larger repository get a scoped tag.
- **Mandatory reason**: once an item is in a baseline every edit and every import row for it needs a reason.
- **Diff**: any two baselines or a baseline and the working copy; added / removed / changed items with field-level, word-level before/after, document filter, GUI view with struck-through deletions and underlined insertions, export to HTML/DOCX/PDF/CSV/JSON. Configuration is read as it was at that baseline.
- **Outputs from a baseline**: `rvs export --baseline X`; every output names the baseline (or "working copy (latest baseline: X)").
- Frozen build: baseline create/list/verify/diff and a PDF export from a baseline were run from `dist/rvs-studio/rvs`.

Defect found and fixed on the way (V18): with a Git-tracked project Doorstop ran `git add` via a subprocess on every save (wrong working directory, or no git installed). Disabled and tested; it affected all earlier milestones for Git projects.

Quality
- 376 tests (+5 perf): Git facade (subfolder repos, deletions, unsigned commits despite a global signing config), baselines (manifest, tag, immutability, promotion, CR gate/deferral, tamper detection, reason rule), change requests, diff (word segments, added/removed/changed, stamp-insensitivity, baseline vs baseline, old configuration), CLI, 17 GUI tests, offline test creating a baseline and diff with sockets blocked.

Caveats
- A baseline commits everything in the project folder, including uncommitted edits (D57). No remote operations (push/pull stay with the user's normal Git workflow).
- Change request workflow is status-only (no approvals/signatures: out of scope for v1); status names are placeholders (TODO-COMPANY).
- Word diff shows deletions and insertions side by side; very long statements are not wrapped into columns.
- Windows and Python 3.11 still untested.
