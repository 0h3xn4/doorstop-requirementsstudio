# Deviations from / limits of the base framework (Doorstop 3.2)

| # | Issue | Handling |
| --- | --- | --- |
| V01 | **Resolved (strict, per user: no network at all).** Doorstop 3.2 hard-depends on `requests`, `bottle`, `plantuml-markdown` and imports `bottle`/`plantuml_markdown` at import time. | `rvs_core/adapter/_offline_guard.py` registers inert placeholder modules for `bottle` and `plantuml_markdown` before Doorstop is imported, so `requests`, `urllib3`, `ssl`, `http.client` are never loaded (Doorstop source untouched; the HTML publisher is unusable inside RVS, which is fine: RVS has its own exporters; plain `doorstop publish` on the project folder is unaffected). The offline test blocks sockets AND asserts that no file-backed network module (requests, urllib3, bottle, ssl, http.client, urllib.request, asyncio, QtNetwork, ...) is in `sys.modules` after GUI + validate. The packages stay installed (pip dependency of Doorstop) and listed in the SBOM, but are excluded from the PyInstaller bundle. |
| V02 | Doorstop `links` can only point to parent-document items in validation. | Typed links are RVS extended attributes (D13), validated by RVS rules, not by Doorstop. |
| V03 | Doorstop extended attributes are not schema-typed. | RVS JSON Schema in `config/` validates them; the adapter coerces on read. |
| V04 | Doorstop has no baseline/change-request concept and writes no history. | Implemented in RVS on Git tags (D14, D15). Requires Git on the workstation (or bundled `dulwich`, pure Python — decide in M0). |
| V05 | Doorstop's `doorstop-server`/Tk GUI are not shipped or started. | Excluded from the PyInstaller bundle (`bottle` module still present for publishers). |
| V06 | Doorstop caches/`.doorstop` temp behaviour may write outside the project. | Adapter runs with `TMPDIR` pointed inside the project folder; verified by a test (spec rule 11). |
| V07 | A Doorstop tree has exactly one root document (`multiple root documents` error). | Derived documents (VER, test specs) are children of a requirements document; their items are `derived: true` and reference requirements through RVS typed links. `rvs-project.yaml` is checked for a single root. |
| V08 | Doorstop 3.2 has no public API to set a document's attribute defaults or fingerprint ("reviewed") attributes, nor to store RVS metadata such as document kind. | Adapter sets the two private fields (`_attribute_defaults`, `_extended_reviewed`) and saves through Doorstop's own `Document.save()`; reads the defaults the same way. Covered by adapter tests; re-check on any Doorstop upgrade. Document kind lives in `rvs-project.yaml`. |
| V09 | Doorstop's validation writes files by default: it stamps unstamped links, reformats link lists, and auto-reviews new items. | Adapter turns off `REFORMAT`, `STAMP_NEW_LINKS`, `REVIEW_NEW_ITEMS` and `REORDER` (module settings, no patching); `link()` stamps explicitly. Test: validation leaves every file byte-identical. |
| V10 | Extended attribute names must not equal Doorstop item fields (`level`, `active`, `normative`, `derived`, `reviewed`, `text`, `ref`, `references`, `links`, `header`): they would overwrite them. | Rejected at config load (`RESERVED_ATTRIBUTES`). |
| V11 | `Document.add_item` reorders and rewrites every item file by default (O(n) saves per add; noisy Git diffs). | Adapter passes `reorder=False`. |
| V12 | Doorstop's own CLI needs a Git working copy at or above the project folder. | Projects live in Git anyway; tests `git init` temp copies before running the CLI. |
| V13 | RVS checks are called directly on item snapshots, not as hooks inside Doorstop's tree validation. | The GUI path must not run Doorstop's validation (it re-parses every item). The hook mechanism remains in the adapter (`issues(item_check, doc_check)`, tested) but `validate_project` no longer uses it. |
| V14 | **Resolved: accepted by the user, then improved by D75 (libyaml: cold open 2.0 s, warm 0.6 s).** Original text: a cold open (no cache) of the 5,000-item project takes 6.0 s against the 3 s target; a warm open takes 0.4 s. Doorstop's `Document.items` parses every file with pure-Python PyYAML, and no public hook selects the C loader. | Warm path meets the target. Options for the cold path: (a) accept it; (b) a read-only libyaml reader verified against Doorstop on a sample (deviates from "Doorstop API for all reads"); (c) parallel parsing. |
| V15 | **Accepted by the user.** python-docx needs `lxml` and ReportLab needs `Pillow`: both are compiled extensions (wheels exist for 3.11-3.13; pip must not need a compiler). Rule 10 prefers pure Python; the spec names these libraries. | Accepted; the release check is `pip install` on the newest Python (done on 3.13 in CI) and `sh scripts/sbom.sh` lists them. Fallback if a future Python lacks wheels: a small own DOCX writer (zip + XML). |
| V16 | **Resolved after M6:** ReqIF import/export implemented (D73). Remaining caveat: the official ReqIF XSD cannot be fetched offline, so files were checked structurally (element order, resolving references, unique identifiers) and by round trips, not against the XSD. Not supported: `.reqifz` archives, embedded files/images, attribute definitions of type REAL/DATE beyond text, multi-valued enumerations beyond a joined list. | Send the message of any tool that rejects an RVS file; foreign-file behaviour is covered by a hand-written sample only. |
| V17 | A running export lowers `sys.setswitchinterval` process-wide (D53). | Restored when the last job ends. |
| V18 | **Defect found and fixed in M5.** When a project is inside a Git repository, Doorstop runs `git add` / `git rm` through a subprocess on every item save. It needs a `git` executable and uses the *process's* working directory, so it could stage files in an unrelated repository or fail outright without git. This affected M1-M4 for any Git-tracked project. | Adapter sets `doorstop.settings.ADDREMOVE_FILES = False` (public setting); test: saving in a Git project with an empty PATH spawns no process and stages nothing. |
| V19 | Doorstop scans every folder below the project root for documents, so extracted baseline snapshots would appear as duplicate documents ("multiple root documents"). | `.rvs-cache/` carries Doorstop's own `.doorstop.skip-all` marker. |
| V20 | `dulwich` (pure-Python Git, `Apache-2.0 OR GPL-2.0-or-later`; used under Apache-2.0) is a runtime dependency, confined to `rvs_core/vcs`. It declares `urllib3` as a dependency, which stays installed but is never imported (excluded from the bundle); only local operations are used, commits and tags are never signed. | Layering test: only `rvs_core/vcs` imports dulwich; the offline test creates a baseline and a diff with sockets blocked. D17 is confirmed. |
| V21 | The adapter uses Doorstop's private `Document._iter()` to list item objects without parsing them (`Document.items` parses every file to test `active`). Doorstop's setters save without loading, so `_item()` loads the object it returns. | Covered by tests/test_cache.py (one edit parses one file) and the diff tests that caught the unloaded-save case. |
| V22 | **Windows is still untested**: `install-windows.ps1`/`uninstall-windows.ps1` and the Windows build were written but never run. Code signing is a hook (`RVS_SIGN_CMD`); no certificate is configured. | Run `rvs selftest --manifest` on a Windows machine before a Windows release. |
| V23 | The quick-start and guide contain no screenshots; the screen descriptions follow the labels in the application. | Add images in a later release if wanted. |
| V24 | Review findings that are deliberately **not** fixed: typed links carry no stamp so they never become suspect (design); Git tags can be moved by anyone with write access to the repository (verify checks content digests, not tag identity; protect tags on the server); a baseline commit does not include symbolic links to folders. The other small findings (duplicate YAML keys, level ordering, free attributes redefining template attributes, atomic item writes, the shared cache temp file, ReqIF values outside the vocabulary, shortcut collisions, live system theme, non-Exception worker errors, stale comparison results) were fixed afterwards (tests/test_small_findings.py). | Documented so they are visible. |
| V25 | The Windows installer was rewritten after the review (literal paths, UTF-8 manifest, strict file list, staged swap) but, like the rest of the Windows path, has never been run on Windows (V22). | A Windows run is still the first thing to do before a Windows release. |
