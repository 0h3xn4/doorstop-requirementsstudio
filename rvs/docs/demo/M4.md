# M4 demo note

```
rvs export examples/satellite300 --vcm --format xlsx -o vcm.xlsx
rvs export examples/satellite300 --spec --format pdf -o spec.pdf
rvs export examples/minimal10 --items --format xlsx -o items.xlsx      # edit it in Excel ...
rvs import examples/minimal10 items.xlsx --dry-run                     # ... preview, then drop --dry-run
rvs-studio  ->  File > Export…   /   File > Import Items…
```
What works
- **Outputs:** every matrix (VCM, traceability, coverage, impact) as CSV, JSON, XLSX, HTML, DOCX or PDF; specification documents (per document or whole project) as HTML, DOCX or PDF; the items table as CSV or XLSX. Each carries a provenance block (project, baseline, date, user, tool/framework versions); gaps are shaded; the VCM states that its layout is a placeholder until the ECSS text is supplied. HTML is self-contained for customers without the tool; PDF embeds IBM Plex.
- **Import (CSV/XLSX):** exact round trip - exporting and re-importing changes no file; a file with only `id,title` updates only titles; new rows create items (explicit IDs honoured); parents and typed links, flags, levels are importable; unknown columns, bad vocabulary values, missing parents, wrong parent document, duplicate IDs and baselined items without a reason are reported per row, and nothing is written unless the plan is clean (or `--skip-errors`). Every imported change is recorded in the item history.
- **GUI:** export dialog (content, format, document filters, destination) and import preview dialog; exports run on a worker thread - a test checks the window keeps processing events while a 340-item PDF is written.
- **Frozen build:** `dist/rvs-studio/` now holds both `rvs-studio` and `rvs`; all formats were exported and an import dry run executed from the frozen CLI.

Quality
- 302 tests (+4 perf): per-format structure checks (python-docx, openpyxl and pypdf read the files back), byte-identical regeneration for every format, Hypothesis round trips (export -> import unchanged; export -> import into an empty project reproduces the export; random seeds 1-6 checked), golden files for all 29 outputs on minimal10 and satellite300, offline test runs every exporter with sockets blocked.

Caveats
- ReqIF is not implemented (deferred by decision).
- Large exports are slow but non-blocking: 5,000-item specification DOCX takes 23 s, PDF 9 s.
- DOCX/PDF layout is functional, not designed to a customer template; templates (export layouts in config) are M6 polish.
- PDF golden hashes are compared on Linux only. Windows and Python 3.11 are still untested.
