# M1 demo note

> **Point-in-time snapshot.** Written when this milestone was finished: test counts, timings, caveats and command forms were true then and are not updated. For the current state see the user guide, `docs/DECISIONS.md`, `docs/DEVIATIONS.md` and `docs/RELEASE.md`.


```
rvs validate examples/minimal10          # exit 0, info only
rvs validate examples/minimal10 --format json
```
- `examples/minimal10`: 10 items in SYS (root), EPS, VER (child of SYS). Valid for plain Doorstop (`doorstop` CLI passes in a Git working copy; tested). Regenerated byte-identically by `rvs_core.examples.minimal` (golden test against the committed copy).
- `rvs_core.adapter`: only Doorstop importer; RVS data = extended attributes; fingerprint attributes (title, type, verify_method, verify_level) so a status change does not create suspect links but a title change does (tested); review via Doorstop's API.
- Schema versions on project file, config files and items: older migrates in memory, newer refused (exit 3), tested with an injected migration chain.
- Config: 6 files + project file, each with a JSON Schema; unresolved standard values are listed, not invented (`RVS-STD-PLACEHOLDER`).
- Tests: 73 (adds Hypothesis round-trip of YAML-hostile strings and byte-identical regeneration). The offline test now runs `validate` on Doorstop with sockets blocked.
